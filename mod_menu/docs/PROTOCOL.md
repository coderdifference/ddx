# Mod menu protocol v1

All messages except `load` and `unload` include `campaign`, the opaque host token. Host events are trusted internal events generated by DDX. Every dispatch returns a view; an `error` means the action failed. The host must enforce pause ownership independently of the controller's token checks.

| Event | Additional properties | Meaning |
| --- | --- | --- |
| `load` | `campaign`, `schemas` array, `saved` object or null | Clear old state; set validated active schemas and restored committed values. Menu remains closed. |
| `unload` | none | Immediately clear all campaign state. |
| `open` | `paused: true` | Host activated the campaign pause-menu row. Clear selection. |
| `select` | `mod` stable ID | Discard prior draft; restore selected mod's values and defaults. |
| `edit` | `field`, `value` typed JSON | Validate one draft field; never save yet. |
| `save` | none | Commit selected mod's entire draft through native campaign save. |
| `close` | none | Discard draft; return to pause menu. |

View properties: `version:1`, `open`, fixed `width:960`, `height:640`, `leftWidth:260`, `mods:[{id,title}]`, `selected` or null, `schema` or null, `values` or null, `error` or null, `canSave`. `schema:null` requires a completely blank right panel. Escape has host ownership: close the modal first, never resume through it. Views contain copies; native must not retain managed pointers after release.

Save payload is `{ "stable.mod.id": { "field_id": value } }`. Unknown mod/field keys survive successful saves. Schema version is authoring format version 1; field IDs and choice IDs must remain stable across releases. A future breaking semantic migration needs a separately specified migration API; do not rename IDs and expect data conversion.

The example `examples/options.json` includes all field kinds. Every field requires `id`, `label`, `type`, `default`. `integer` and `float` optionally accept inclusive `min`/`max`; `text` accepts `maxLength` (default 4096 UTF-16 code units, up to 65536). `single`, `multi` and `enum` require `choices:[{id,label}]`. Single/enum values are choice ID strings; multi values are unique ID arrays, which may be empty. Integers are signed 32-bit; floats are finite double values. No implicit type conversions. Saved invalid values fall back to the field's valid default. Duplicate field/choice IDs, unsupported types/versions, invalid defaults and reversed bounds reject the schema.


C# client extension requests use `{event, schema, values}` for build/validate and `{event, values}` for loaded/changed/unloaded. Replies use `{schema, values, error}`. A nonempty error vetoes build/validate; replacements are validated before use. Returned schema is accepted only for build, and cannot change the mod ID. Loaded/changed values are raw committed data; absent keys require author defaults. The extension ABI is `modmenu_form_register(schema, dispatch, release)`, `modmenu_client_event(id, request)` and `modmenu_values(id)` in native `common.h`. The latter two return borrowed UTF-8 valid until the next values/event call; callers copy immediately.

Native dialog geometry is controlled by `engine/ui/dialog.layout.json` under `modmenu`; these settings override the service view geometry hints. The native default is 1280 by 800 logical units, scaled to fit the viewport, with padded panels and a fixed button footer.
